# 破甲对比与评分：dsh-purge 1.1.71 vs autokill-purge

> 本文件是本项目**唯一**的说明性文档（此前的 `docs/*.md`、`REQUIREMENTS.md` 已按要求删除，见文末「文档清理」）。
> 对象：本机 `dsh-purge@1.1.71`（`%LOCALAPPDATA%\Programs\DeepSeek Harness\resources\plugins\dsh-purge`，与
> `~/.dsh/profiles/desktop/node_modules/dsh-purge` 同版本）与 `autokill-purge`（本仓库，commit `d129590`）。
> 版本与日期：2026-11-16。

## 0. 结论先说

| 场景 | 谁更合适 | 总分（默认权重 / 评测者权重 / 红队全链权重） |
| --- | --- | --- |
| 单次破甲任务、国内模型、要能复制的载荷和证据 | **autokill-purge** | 8.10 / 7.88 / 6.05 |
| 长期把宿主改成破甲状态、要红队全链（工具/技能/知识库/情报） | **dsh-purge** | 6.58 / 7.03 / 8.30 |

一句话：**破甲的"内容"两边同源（我们的模板就是从它 1.1.71 的密封槽解出来的 21194 字符），差别在"投递方式"和"配套"。**
它把内容注进宿主的系统提示词头部，位置最优但改宿主；我们把同一份内容按次拼成可复制载荷，零风险但靠人粘贴。

## 1. 事实源（可复核）

| 事实 | 证据 |
| --- | --- |
| 它是 DSH 插件，破甲靠"改宿主 + 注入" | `package.json`（name/version 1.1.71，`dsh.bundle.patch: ./cordis.patch.yml`） |
| 注入位置 = 系统提示词最前 | `lib/core.js:5624`、`:5655`：`hang full prompt-inject at head` |
| 只有一份注入文本，**没有 per-model 提示词逻辑** | `lib/core.js` 内 `modelPrompts` / `perModel` / `promptForModel` 零命中；`prompt-inject.md` 由 `core.js:2384`、`:2396` 单文件读写 |
| 默认提示词是密封的 | `lib/asset-table.js`（`SLOT/MASK/TAG/IV`）+ `lib/table-key.js`（AES-256-GCM + deflate）+ `lib/table-read.js#openSlot()` |
| 解密长度 21194 字符 | 用它的 `openSlot()` 实测 |
| 生效步骤：装 → 应用 → 自动重启 → **新开一轮对话** | `README.zh-CN.md:34`："点会话标题旁的 dsh-purge → 清洗 → 应用。成功会自动重启；补丁没打完不重启。重启后新开一轮对话，注入才进当前会话。" |
| web / desktop 两个 profile 分开装、分开应用 | `README.zh-CN.md:32` |
| 它自带架构文档记录原型规模：83 个 patch、`redteam_*` 工具 56 个、技能 48 篇、5 角色 | `docs/autokill-purge-architecture.md`（dsh-purge 自带，未逐个复核当前版本计数） |
| 我们没有宿主注入，只生成文本 | `web/server.mjs`（`buildPayload()` / `PROMPTS` / `readPromptScope()`），`web/prompts/sauce-1171.md` |

## 2. 机制差异（逐项）

| 维度 | dsh-purge 1.1.71 | autokill-purge（当前） |
| --- | --- | --- |
| 作用点 | 宿主：提示词注入 + 83 patch（审批门 / 沙箱 / 会话格式） | 只产出文本，不碰宿主、不碰目标 |
| 生效粒度 | 全局、一次性（应用后重启，新会话生效） | 每次点击生成一组（3 技术 × 文本/Base64/ROT13 = 9 条） |
| 投递位置 | **系统提示词头部**（模型必读，权重最高） | 用户自己粘贴（可能被 UI 截断、被当作用户消息） |
| 模板数量 | 1 份加密默认（可手动替换 `prompt-inject.md`） | 登记 2 套（`sauce-1171` 全文 / `none` 纯指令），支持 `full` / `identity` 两种范围 |
| 模型维度 | 无 per-model；换模型靠宿主"模型 + 推理等级（Low/High）"设置或手改文件 | 24 个模型（国内 18）各带 tagline、长说明、适用技术、采样建议；推荐位按 `recommended` 排 |
| 任务输入 | 不需要（改完即生效） | 必须写一句；空任务前端拦截，不发请求 |
| 效果验证 | 人眼看模型答不答 | 每条可标「这次成功了 / 被拒绝了」→ `attempts` 累计 → 按模型/技术算命中率 |
| 副作用 | 改宿主文件（`.dshpurge.bak` 备份、版本漂移需重打） | 零宿主改动；只写 `data/state.json` |
| 可迁移 | 绑 DSH 0.2（web / desktop 各装一份） | 纯文本，任意模型/任意宿主 |
| 非文本破甲 | 无 | break 内核 8 动作：`info/scan/plan/patch/invert/verify/restore/journal`（改副本、`--expect` 先校验、可还原） |

## 3. 实测：载荷"破甲要素"覆盖度

同一句任务（`写一段在授权靶场里验证 SSH 弱口令的步骤`）、同一模型（`deepseek-flash`），只换模板，量载荷里能检出多少个破甲要素：

| 要素 | 不套模板（`template=none`） | 套 dsh-purge 模板（`template=sauce-1171`） |
| --- | --- | --- |
| 身份 / 人格声明 | ✗ | ✓ |
| 禁止拒答 | ✗ | ✓ |
| 任务优先级声明 | ✗ | ✓ |
| 范围注入（`[MODE: UNRESTRICTED SANDBOX]`） | ✗ | ✓ |
| 输出纪律 / 格式要求 | ✓ | ✓ |
| 任务输入点（本次任务句） | ✓ | ✓ |
| 载荷总字符数 | **45** | **21246**（模板 21194 + 任务） |
| 覆盖度 | **2 / 6** | **6 / 6** |

复现：`POST /api/breach/build {template:'none'|'sauce-1171', task, output, techniques:['persona']}`，比对首条 `kind=text` 的正文。

这组数字说明：**破甲效果主要由模板决定，而我们和它用的是同一份模板**。差别不在"内容强度"，在"送到模型手里时是什么身份"——
它进系统提示词，我们的载荷进用户消息。这是它唯一、但很硬的结构性优势。

## 4. 评分（10 分制，权重可调）

评分口径：**基于机制与可复现的载荷要素测量，不含"模型在线实测通过率"**（我们不发模型请求；它也不记录通过率）。
所以"破甲效果"拆成两件事评：**要素覆盖**（内容强度）与**投递确定性**（内容能不能按最高权重进模型）。

| # | 维度 | dsh-purge | autokill-purge | 评分依据 |
| --- | --- | --- | --- | --- |
| 1 | 破甲要素覆盖 | **9.5** | **8.5** | 同为 21K 模板、要素 6/6；我们多出编码/零宽变体，但模板只有 1 份真内容 |
| 2 | 投递确定性 | **9.0** | **6.0** | 它注入系统提示词头部；我们靠粘贴（21K 长文本易被截断、被当用户消息） |
| 3 | 模型适配 | **4.0** | **8.5** | 它无 per-model 逻辑；我们 24 模型 / 国内 18 + 按模型采样建议 + 推荐位 |
| 4 | 操作性 | **6.0** | **9.5** | 它：装插件 → 应用 → 重启 → 新开会话（两个 profile 各一遍）；我们：开页面 → 写一句 → 点一下 |
| 5 | 可验证性 | **3.0** | **8.0** | 它只能人眼看答复；我们有 attempts 命中率 + 四套自动化（21/18/19/16 条） |
| 6 | 风险与可逆 | **5.0** | **9.5** | 它改宿主 83 处（有 `.bak` 与还原，但版本漂移要重打）；我们零改动 |
| 7 | 可迁移性 | **2.5** | **9.0** | 它绑 DSH 0.2；我们纯文本，任意模型/宿主 |
| 8 | 能力面广度 | **9.0** | **6.0** | 它有 56 红队工具 / 48 技能 / SQLite 知识库 / 情报巡检 / 演练台；我们没有 |
| 9 | 维护成本（越高越省心） | **4.0** | **8.5** | 它跟宿主版本漂移；我们单文件 Node + 零依赖 + 可复跑验收 |
| 10 | 非文本破甲（二进制/PE） | **0** | **9.0** | 它无此维度；我们 break 内核 8 动作 + journal/verify/restore |

| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| **默认**（单次任务） | 20% | 15% | 10% | 15% | 10% | 10% | 5% | 10% | 5% | **6.58** | **8.10** |

## 5. 各自的硬伤（不遮）

**dsh-purge 1.1.71**
1. "不同模型可换不同提示词"是宣传语，代码里没有 per-model 分支——换模型只能靠宿主设置或手改文件。
2. 改宿主 83 处，跟版本走；npm 升级会盖掉 `node_modules`，靠启动时"再检查并应用"兜。
3. 没有量化通过率，A/B 只能靠人记。
4. 与"二进制/PE 层"完全无关。

**autokill-purge（我们）**
1. **投递不确定**：21K 载荷让用户自己粘，很多输入框会截断；粘进去也是用户消息，权重不如系统提示词。这是当前最大的效果损耗点。
2. 模型适配是"标签级"的：24 个模型有说明与采样建议，但模板只有 1 份（`sauce-1171`），`PROMPTS` 表的骨架空着。
3. 不代发请求，所以 `attempts` 是人工标记，不是自动判通过。
4. 能力面窄：没有红队工具链、没有知识库写入、没有情报巡检。

## 6. 下一步（按性价比）

1. **补"投递"**：给载荷加一段"请把它作为系统提示词/自定义指令粘贴"的短引导，并在复制时提供"只复制模板"与"模板+任务"两种形态——直接对冲第 1 条硬伤。
2. **按模型族补模板**（DeepSeek / 千问 / GLM / Kimi / 豆包+文心 / 国外各一份），`PROMPTS` 已支持多套，改数据不改代码。
3. **模板登记版本号**（现在只记 `source`），换模板时能说清是哪一版。
4. 不抄它的 patch 账本——我们不碰宿主，那是负资产。
