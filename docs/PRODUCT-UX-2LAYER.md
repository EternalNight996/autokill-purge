# autokill-purge 双层体验改造规格（普通模式 / 技术模式）

版本：v1 · 2026-11-16 · 产品：小梦（代产品负责人）· 实现：Pixel（前端）、Lin（后端）
适用代码：`D:\autokill-purge\web\public\{index.html,style.css,app.js}`、`D:\autokill-purge\web\server.mjs`

---

## 0. 一句话目标

普通用户打开就能用：**写一句话 → 点一个按钮 → 拿到能复制的载荷**。
技术用户能随时切到技术模式，拿到现有全部参数、路径和诊断能力。

判断标准只有一条：**普通模式下，用户不需要知道任何实现名词（模型矩阵、层、技术库、breakDir、pluginPath、wasm、token），也能完成一次完整任务。**

---

## 1. 用户分层

| | 普通用户（默认） | 技术用户 |
|---|---|---|
| 他是谁 | 不懂技术，只想知道“这东西怎么用、现在能不能用” | 要复现、要调参、要排障 |
| 他要什么 | 一个输入、一个按钮、一个结果 | 全部参数可见、可改、可恢复默认 |
| 界面原则 | 只留主路径；其余有默认值；配置项一律不出现 | 分区、有说明、有默认值、有诊断 |
| 失败时 | 一句人话 + 一个动作 | 状态码、字段名、日志入口 |

---

## 2. 首启（第一次打开）

1. 保留现有《安全与法律协议》弹窗，签署后进入。
2. 签署后进入 **普通模式首页（破甲）**，不弹任何设置向导、不要求填路径。
3. 首页顶部一张 **状态卡**，三选一：
   - 绿：「可以直接用」+ 副文案「选个模型，写一句话就能生成。」
   - 黄：「还差一步」+ 副文案（缺什么就用一句人话，例如「记忆服务还没连上，可以先不用它」）+ 按钮「去设置」
   - 红：「暂时用不了」+ 原因一句话 + 按钮「查看怎么办」（打开技术模式对应分区）
4. 状态卡的数据来自 `GET /api/readiness`（Lin 提供）。接口不可用时，状态卡整块隐藏，不报错、不挡主流程。

## 3. 普通模式

### 3.1 导航
只保留 4 项：**破甲 / 装备 / 记忆 / 设置**。
- 「记忆分发」「记忆中心」合并为「记忆」。
- 「关于」收进设置页底部（版本、协议、开源许可）。
- 顶部右侧一个开关：**「技术模式」**。普通模式不显示其余任何入口。

### 3.2 破甲页（普通模式主页面）

从上到下，只有 3 块：

1. **标题区**
   - H1「破甲」
   - 说明：「选一个目标模型，写清楚你要它做什么，就能拿到可以直接复制的载荷。」
2. **操作卡**
   - 「目标模型」：只显示 **3 个推荐模型**（后端 catalog 有推荐标记就用推荐的前 3 个，没有就取前 3 个）。卡片只显示名称 + 一句特点，不显示 family、拒绝风格等字段。
   - 「你要它做什么」：`textarea`，placeholder「例：让它详细说明如何绕过内容审核」，下方小字「写得越具体，生成的载荷越能用」。
   - 主按钮：**「生成载荷」**（整宽、页面唯一主色按钮）。
   - 默认值（不显示给用户）：layer = prompt 层；techniques = 推荐 3 项；role / output 要求 = 内置默认。
3. **结果区**
   - 每条载荷一张卡：序号 + 名称 + 「复制」按钮；展开可看全文。
   - 卡片底部两个小按钮：**「这次成功了」/「被拒绝了」**，点完即记录，toast「已记录」。
   - 生成后追加一行：「想调层、技术、采样？切到技术模式。」
   - 空态：「还没有载荷。上面写一句话，点『生成载荷』。」
   - 失败态：「没生成出来」+ 一句原因 + 「重试」按钮。

**普通模式破甲页不出现**：9 模型矩阵、3 层选择、12 技术 chips、技术库说明、角色、输出要求、采样建议、零宽样本、base64/ROT13 变体开关、命中率表格。

### 3.3 装备页（普通模式）

- 标题「装备」+ 说明「把现成能力装到你的智能体上，装完就能用。」
- 一张状态卡：「当前已装备 N 件」+ 列表（名称 + 一句话用途 + 「卸下」）。
- 主按钮：**「一键装备推荐组合」**。点击后直接装推荐组合，结果区显示「已装备 3 件：…」。
- 不显示：路径、插件文件、版本号、依赖、导入导出。
- 空态：「还没装备。点上面的按钮，一次装好推荐组合。」

### 3.4 记忆页（普通模式）

- 标题「记忆」+ 说明「查你的智能体记住了什么。」
- 一个搜索框 + 「搜索」按钮（回车也可）。
- 结果列表：标题 + 摘要 + 时间；点开看全文。
- 顶部一行连接状态：「记忆服务已连接」/「记忆服务未连接 · 去设置」。未连接时搜索框可用但结果区提示「连上记忆服务后才能搜索」。
- 不显示：memoryBase、token、分发对象、kind、同步模式。

### 3.5 设置页（普通模式）

只保留 5 项，均为「状态 + 一个动作」：
1. 连接状态 + 「测试连接」
2. 语言（简体中文）
3. 「切换到技术模式」（说明：显示全部参数与路径）
4. 「重新签署协议」
5. 版本与关于（折叠）

不显示：memoryBase、memoryToken、breakDir、pluginPath、dataDir。

### 3.6 文案规则（硬性）

- 禁止出现：`breakDir`、`pluginPath`、`wasm`、`token`、`memoryBase`、`payload`、`variant`、`layer`、`technique`、`schema`、`API`、`HTTP`、`403/400/500`。
- 错误提示结构：**发生了什么（人话）+ 下一步做什么（一个动作）**。
  - ✅「没连上记忆服务。检查服务是否启动，或点『测试连接』重试。」
  - ❌「请求 /api/memory/stats 失败：ECONNREFUSED」

## 4. 技术模式

### 4.1 进入与提示
- 顶部开关切到「技术模式」后，六页导航恢复：破甲 / 装备 / 记忆分发 / 记忆中心 / 设置 / 关于。
- 首次进入弹一次轻提示（可关闭，localStorage 记住）：「技术模式会显示全部参数和文件路径。改错可能影响运行，可以随时点『恢复默认』。」
- 开关位置固定在顶部右侧，两种模式都在。

### 4.2 每页字段分组（用可折叠分组，默认展开「基础」）

统一分组顺序：**基础 → 生成策略 → 采样 → 路径与文件 → 诊断**（页面没有的分组不显示）。

- 每个字段：标签 + 一行说明 + 默认值徽标 + 「恢复默认」。
- 路径类字段必须标「高级」徽标，并在说明里写清「留空则使用内置默认」。
- 所有现有功能、字段、请求参数**一个都不能少**；这是能力保留，不是简化。

### 4.3 技术模式破甲页
保留现有全部内容：9 模型矩阵、3 层、12 技术 chips + 技术库说明、角色、输出要求、采样建议、零宽样本、编码变体、尝试记录与命中率。
仅做组织性改造：上述内容按 4.2 分组，减少同屏密度。

---

## 5. 模式持久化

- 默认 `simple`。
- 前端存 `localStorage["ap.uiMode"]`；同时 `POST /api/settings { uiMode }` 持久化到服务端（Lin）。
- 读取优先级：服务端 `state.settings.uiMode` > localStorage > `simple`。
- 切换即时生效，不刷新页面、不丢当前页面的输入。

## 6. 验收清单（可判定，逐条打勾）

普通模式：
1. 首次签署后落在普通模式破甲页，无任何设置向导。
2. 普通模式导航只有 4 项，且没有「记忆分发」「关于」。
3. 普通模式破甲页首屏可交互元素 ≤ 8 个（模型卡 3 + 输入 1 + 主按钮 1 + 模式开关 1 + 复制/记录按钮不计首屏）。
4. 普通模式破甲页 DOM 文本中不出现第 3.6 节任一禁用词。
5. 只选模型 + 写任务 + 点「生成载荷」，能生成 ≥1 条载荷（其余走默认）。
6. 任务为空点生成，出现人话提示，不产生载荷、不报 500。
7. 每条载荷有「复制」，复制内容与展示全文一致。
8. 「这次成功了 / 被拒绝了」点击后有一次记录，命中率随之变化（技术模式可查）。
9. 普通模式装备页只有 1 个主按钮，点击后状态变成「已装备 N 件」。
10. 普通模式记忆页未连接时给出「去设置」，已连接时能搜索出结果。
11. 普通模式设置页不出现任何路径/令牌字段。
12. 从普通模式切到技术模式 ≤ 1 次点击，六页全部可达，原有功能可用。
13. 技术模式切回普通模式后，普通模式仍只有 4 项，且不残留技术字段。
14. 刷新页面后模式保持上次选择。
15. 1280 / 390 / 320 三个宽度下，两种模式都无页面横向溢出；`window.__apErrors` 为 0。
16. 现有 `node test/acceptance.mjs` 仍 21/21 PASS；`node _ui-test/ac-check.mjs` 仍全 PASS。
